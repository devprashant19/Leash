Spending limits for AI agents, written once in Fe.

Leash gives an AI agent a Safe wallet with limits. The same Fe policy code is compiled twice: into a Safe module that enforces the limits on-chain, and into a native leash CLI that predicts every verdict before a transaction is sent. Both print the same policy fingerprint, so they cannot drift.

How it works

One pure policy ingot holds every rule. The contract and the CLI are thin shells around it.

1. Agent proposes

(to, value, data, operation) for its Safe.

2. CLI predicts

leash check (native, Fe) runs policy::decide and prints ALLOW or DENY with the reason.

policy ingot

decide declares no effects. record is the only code that changes spending state.

3. Module enforces

LeashModule (EVM, Fe) runs the same decide; only allowed calls reach the Safe.

The demo policy

  • At most 0.1 ETH per transaction, 0.5 ETH per rolling 24 h.
  • Token transfers up to 100 tokens; approvals up to 100, never unlimited.
  • Delegatecall is always refused.
  • Only listed contracts, functions and recipients; anything else is refused.
